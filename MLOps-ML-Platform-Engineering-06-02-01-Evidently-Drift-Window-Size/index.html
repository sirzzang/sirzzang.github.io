    서종호(가시다)님의 Machine Learning Platform Engineering Study 3주차 학습 내용을 기반으로 합니다.


    TL;DR

    • 데이터 드리프트는 모델에 들어오는 입력의 분포가 학습 때와 달라지는 현상이다. Evidently는 학습 데이터와 최근 요청을 비교해 드리프트를 판정한다
    • 책의 실습은 학습 데이터에 있던 사용자의 값을 다시 모델에 넣는다. 입력이 달라지지 않았으니 드리프트가 없어야 하는데 컬럼의 절반 이상이 드리프트로 판정됐다
    • 원인은 표본 오차다. 최근 요청 50건이나 100건만 모으면 범주 비율이 학습 데이터와 우연히 달라진다. Evidently의 기본 판정은 분포 차이가 고정된 기준을 넘는지만 보므로 이 우연한 차이와 실제 변화를 구분하지 않는다
    • 같은 데이터에서 윈도(비교에 쓰는 최근 요청 묶음)를 5000번씩 뽑아 판정했다. 드리프트 판정 비율은 윈도 50에서 98%, 100에서 57%, 200에서 1%였다
    • 윈도 크기는 범주 수와 허용할 오경보(변화가 없는데 드리프트로 나온 판정) 비율로 정할 수 있다. 윈도를 키우기 어려우면 판정 방법을 chi-square 검정으로 바꾸는 방법이 있고, 표본이 아주 크면 반대로 작은 변화까지 판정되는 문제가 생긴다


    들어가며

    데이터 드리프트(data drift)는 모델에 들어오는 입력의 분포가 학습 때와 달라지는 현상이다. 학습 데이터에는 30대가 많았는데 서비스 요청에는 60대가 많아지면 모델 성능이 떨어질 수 있다. 그래서 성능이 떨어지기 전에 점검이나 재학습으로 연결하기 위해 드리프트를 감시한다. 4.1.1편에서 학습 트리거 구간을 이야기하며 드리프트 신호는 뒤의 모니터링 장에 미뤄 두었다. 모니터링 장은 책 6장이고 드리프트는 그중 6.2절에서 다룬다.

    3주차에 읽은 책 머신러닝 플랫폼 엔지니어링 6장의 실습은 소득 분류기를 BentoML로 배포한다. 서비스는 최근 요청 N건을 윈도(window)에 모아 학습 데이터와 비교한다. 요청 하나가 표의 한 행이므로 윈도 크기 50은 50행이다. 실습의 요청은 학습 데이터에 있는 사용자의 ID를 보내고 서비스는 피처 저장소에서 그 사용자의 값을 읽어 윈도에 넣는다. 윈도의 값이 모두 학습 데이터에서 왔으니 입력이 달라진 것이 없고 드리프트가 나오지 않아야 한다.

    그런데 책은 윈도 크기가 50일 때의 대시보드(그림 6.21)에서 드리프트 컬럼 비율이 0.875에 가깝다고 적는다. 범주형 컬럼 8개 중 드리프트로 판정된 컬럼의 비율이니 8개 중 7개가 넘은 셈이다. 책도 이 수치를 다소 이상하다고 보고, 윈도 크기 때문일 수 있으니 임곗값을 재검토하고 더 큰 윈도를 시도해 보라고 권한다. 스터디 실습의 대시보드 캡처는 윈도 100에서 0.5였고, 스터디 자료는 표본이 작으면 거리 기반 판정의 값이 크게 나오기 쉽다는 설명을 덧붙였다.

    그 값은 얼마나 크게 나올까. 왜 8개 중 4개, 7개가 기준을 넘었을까. 윈도를 얼마나 키워야 같은 분포에서 드리프트 판정이 나오지 않을까.

    드리프트 판정은 Evidently 라이브러리 안에서 끝나므로 서비스를 띄우지 않고 Python 가상환경에서 돌렸고, 실험 코드를 돌리고 통계량의 해석과 식을 살펴보는 데는 AI의 도움을 받았다. 코드와 데이터, 실행 출력은 실험 폴더에 두었다.


    Evidently의 드리프트 판정

    Evidently는 기준이 되는 reference 데이터와 새로 들어온 current 데이터를 비교하는데, 실습에서는 학습 데이터가 reference이고 윈도가 current다. 판정은 두 단계로 이뤄지고 기준도 둘이다. 먼저 컬럼마다 드리프트를 판정하고, 드리프트로 판정된 컬럼의 비율이 0.5 이상이면 데이터셋 드리프트로 본다.

    flowchart TB
  %% 컬럼마다 판정한 뒤 드리프트 컬럼 비율로 데이터셋을 판정한다
  R[reference] --> C[컬럼별 판정]
  W[current 윈도] --> C
  C --> S[드리프트 컬럼 비율]
  S --> D{0.5 이상인가}
  D -->|예| T[데이터셋 드리프트]
  D -->|아니오| F[드리프트 아님]
    AI를 이용해 직접 그린 도식. 컬럼마다 판정한 뒤 드리프트 컬럼 비율이 0.5 이상이면 데이터셋 드리프트로 본다

    컬럼 판정의 방법은 컬럼 타입과 reference 크기에 따라 달라지고, 데이터셋 기준 0.5는 기본값이라 컬럼 8개 중 4개가 넘은 경우도 드리프트로 센다(소스).

    책이 쓰는 버전 0.5.0의 기본 규칙은 다음과 같고 2026년 11월의 Evidently 문서에 적힌 규칙도 같다. 실습 데이터는 범주형 8개 컬럼이라 여기서는 범주형 칸만 쓴다.

    reference 행 수 범주형 수치형
    1000 이하 chi-square, 값이 2개면 Z 검정 KS 검정, 값이 5개 이하면 chi-square나 Z 검정
    1000 초과 Jensen-Shannon 거리 Wasserstein 거리, 값이 5개 이하면 Jensen-Shannon 거리

    거리와 가설 검정

    표의 방법은 거리와 가설 검정 두 종류이고 답하는 질문이 다르다. 어떤 컬럼의 범주 비율이 학습 데이터에서 A 60%, B 30%, C 10%이고 새 데이터에서 A 50%, B 35%, C 15%라고 하자.

    거리(distance)는 두 분포가 얼마나 다른지에 답한다. 값이 클수록 많이 달라졌다는 뜻이다. 통계에서 효과 크기(effect size)라고 부르는 쪽의 값이고 계산식에 표본 크기가 없다. Jensen-Shannon 거리는 세 단계로 구한다. 먼저 두 분포의 범주별 비율을 평균해 중간 분포를 만든다. 위 예시의 중간 분포는 A 55%, B 32.5%, C 12.5%다. 다음으로 두 분포가 중간 분포에서 벗어난 정도를 각각 KL 발산(Kullback-Leibler divergence)으로 재서 평균한다. 이 값이 Jensen-Shannon 발산이다. 마지막으로 제곱근을 씌우면 거리가 된다. 비율이 같으면 0이고 겹치는 범주가 없으면 최댓값 약 0.833이다. 위 예시의 거리는 0.076이다. Evidently는 이 거리가 0.1 이상이면 드리프트로 판정한다. 범주 2개로 보면 50:50과 64:36의 거리가 0.100이다.

    출처: K687 ypo, Kullback–Leibler distributions example 1, Wikimedia Commons, CC BY-SA 4.0

    왼쪽은 세 값의 비율이 36%, 48%, 16%인 분포이고 오른쪽은 세 값이 3분의 1씩인 분포다. 거리는 이렇게 막대 높이가 다른 정도를 숫자 하나로 줄인 값이고 두 분포의 Jensen-Shannon 거리는 0.150이다.

    가설 검정(hypothesis test)은 그 차이를 우연으로 설명할 수 있는지 따진다. 두 분포가 같다고 가정했을 때 이만한 차이나 그보다 큰 차이가 나올 확률이 p값이다. p값이 작을수록 우연으로 설명하기 어렵고, 유의수준 0.05보다 작은 결과를 유의하다고 말하며 Evidently는 이때 드리프트로 판정한다. 다만 p값은 변화의 크기를 알려 주지 않고, 차이가 우연일 확률이나 판정이 틀릴 확률을 뜻하지도 않는다.

    출처: Repapetilto, Chen-Pan Liao, P-value in statistical significance testing, Wikimedia Commons, CC BY-SA 3.0

    곡선은 가설이 참일 때 결과가 나오는 분포이고 초록색 넓이가 p값이다. 그림 위쪽 상자의 식은 가설이 참일 때 이 결과가 나올 확률과 이 결과를 봤을 때 가설이 참일 확률이 다르다는 뜻이다.

    p값을 읽는 법

    p값 0.05는 판정이 틀릴 확률 5%가 아니다. p값은 차이가 없다고 가정했을 때 지금만큼 또는 그보다 큰 차이가 나올 확률이다. 차이가 없을 때 이런 결과가 나올 확률이고, 이런 결과가 나왔을 때 차이가 없을 확률이 아니다. 판정이 틀릴 확률로 읽으면 이 조건을 뒤집게 된다.

    공평한 동전을 10번 던져 앞면이 9번 이상이거나 1번 이하로 나올 확률은 약 2%다. 공평한 동전이면 이런 결과가 드물다는 뜻이다. 이 동전이 공평할 확률이 2%라는 뜻은 아니다.

    판정이 틀릴 확률을 구하려면 실제 변화가 얼마나 흔한지도 알아야 한다. 판정 1,000번 중 900번은 실제 변화가 없고 100번은 있다고 가정하자. 유의수준은 0.05이고 실제 변화를 잡을 확률은 80%다.

    실제 상황 횟수 드리프트 판정
    변화 없음 900 45(900의 5%)
    변화 있음 100 80(100의 80%)

    드리프트 판정 125번 중 45번은 변화가 없는데 나온 판정이므로 틀린 비율은 36%다. 5%는 변화가 없는 900번 안에서 잘못 판정하는 비율이고 유의수준으로 미리 정하는 값이다.

    p값이 0.03이면 차이가 없을 때 이만한 차이나 그보다 큰 차이가 100번에 3번쯤 나온다는 뜻이다. 차이가 없다는 가정이 데이터와 잘 맞지 않는다고 읽는다. p값이 0.4면 차이가 없다는 증거로 읽지 않고 이 데이터로는 구분하지 못한다고 읽는다.

    chi-square 검정은 범주마다 기대 개수와 실제 개수를 비교한다. 기대 개수는 학습 데이터의 비율에 새 데이터 건수를 곱한 값이다. 새 데이터가 100건이면 기대 개수는 A 60, B 30, C 10이고 실제 개수는 50, 35, 15다. 범주마다 차이를 제곱하고 기대 개수로 나눠 더한 값이 chi-square 통계량이다. 이 예시에서는 100÷60 + 25÷30 + 25÷10 = 5.0이다. 통계량을 자유도(범주 수에서 1을 뺀 값)에 맞는 chi-square 분포와 대조하면 p값이 나온다. 통계량이 클수록 p값이 작다. 이 검정은 행이 서로 독립이라고, 즉 한 행의 값을 알아도 다른 행의 값을 짐작할 수 없다고 가정한다. 유의수준이 0.05면 같은 분포에서도 약 5%는 드리프트로 나오는 것이 정상이고, 기대 개수가 5보다 작은 범주가 많으면 이 비율이 5%에서 벗어난다.

    출처: Geek3, Chi-square pdf, Wikimedia Commons, CC BY 3.0

    그림의 k가 자유도다. 범주가 3개인 예시는 자유도가 2이므로 k=2 곡선을 쓰고 통계량 5.0 오른쪽의 넓이가 p값 0.082다.

    둘의 차이는 예시로 보면 분명하다. A의 비율이 60%에서 50%로 내려갔을 때 거리는 비율만 보므로 건수와 상관없이 0.076이고 기준 0.1보다 작다. p값은 건수까지 본다. 분포가 그대로여도 100건을 뽑으면 이만한 차이나 그보다 큰 차이가 열두 번에 한 번꼴로 나오므로 우연으로도 나올 수 있는 차이로 읽는다. 1,000건을 뽑으면 이만한 차이가 거의 나오지 않으므로 우연으로 보기 어렵다.

    같은 비율 차이에서 표본 크기만 바꾸면 둘의 차이가 보인다.

    새 데이터 건수 Jensen-Shannon 거리 기준 0.1로 판정 chi-square 통계량 p값 유의수준 0.05로 판정
    100 0.076 드리프트 아님 5.0 0.082 드리프트 아님
    1,000 0.076 드리프트 아님 50.0 1.4e-11 드리프트

    이 표는 표본 비율이 정확히 50:35:15로 나왔다고 둔 계산이다. 비율이 그대로이면 거리는 건수가 늘어도 같고 p값은 건수가 늘면 작아진다. 실제 표본의 비율은 뽑을 때마다 달라지고 건수가 적을수록 많이 흔들리는데, 이 흔들림은 뒤의 원인 절에서 다룬다.

    분석할 때는 거리와 p값을 함께 읽는다. 여기서 거리는 앞에서 구한 Jensen-Shannon 거리다. 거리가 크다는 것은 두 분포의 비율이 많이 벌어졌다는 뜻이고 p값이 크다는 것은 그만한 차이가 우연으로도 자주 나온다는 뜻이다. 거리는 기준 0.1, p값은 유의수준 0.05로 크고 작음을 나눈다.

    거리(변화의 크기) p값 읽는 법
    크다 작다 변화가 크고 우연으로 설명하기 어렵다. 점검 대상이다
    작다 작다 변화는 있어 보이지만 작다. 표본이 클 때 흔하다. 앞 표의 1,000건이 이 경우다
    크다 크다 거리는 커도 표본 오차로 설명할 수 있다. 작은 윈도에서 기준을 넘은 컬럼 대부분이 이 경우다
    작다 크다 변화가 없거나 표본이 모자라 알 수 없다. 앞 표의 100건이 이 경우다

    기본 규칙의 소스

    선택 함수에서 범주형 부분만 추리면 조건문에 reference_data의 크기만 있다. 학습 데이터 3만 행을 reference로 두면 윈도가 50이든 5000이든 같은 방법을 쓴다.

    # evidently/calculations/stattests/registry.py (v0.5.0, 발췌)
elif reference_data.shape[0] <= 1000:
    ...
    elif feature_type == ColumnType.Categorical:
        return stattests.chi_stat_test if n_values > 2 else stattests.z_stat_test
elif reference_data.shape[0] > 1000:
    ...
    elif feature_type == ColumnType.Categorical:
        return stattests.jensenshannon_stat_test

    Evidently의 판정은 이 거리를 기본 임곗값 0.1과 비교한다.

    # evidently/calculations/stattests/jensenshannon.py (v0.5.0, 발췌)
jensenshannon_value = distance.jensenshannon(reference_percents, current_percents, base)
return jensenshannon_value, jensenshannon_value >= threshold

    참고: 책은 그림 6.16의 보고서를 바서슈타인(Wasserstein) 거리로 설명한다. 수치형 컬럼의 기본 방법이고 기본 임곗값은 역시 0.1이다. 여기서는 범주형 8개 컬럼만 비교한다.

    원인: 표본 오차

    분포 변화가 없는데 드리프트로 나온 판정이 오경보(false alarm)다. 왜 오경보가 나는지는 표본 오차로 설명된다. 같은 분포에서 뽑아도 표본의 비율은 전체 비율과 조금씩 다른데, 오차는 양쪽으로 나지만 거리는 0 아래로 내려가지 않으므로 그대로 양수 값으로 남는다. 그래서 윈도가 작을수록 오차가 크고 거리도 크다.

    범주가 많을수록 오차가 쌓이는 곳이 많아 거리가 더 커진다. 이 크기를 범주 수 $k$와 윈도 크기 $n$으로 어림하면 다음과 같다.

    범주 16개에 윈도 100이면 0.137이라 표본 오차만으로 기준 0.1을 넘고, 거리를 절반으로 줄이려면 윈도를 네 배로 키워야 한다.

    식이 나오는 과정

    reference가 윈도보다 훨씬 크면 reference의 비율을 참값으로 볼 수 있다. reference의 범주 비율을 $p_i$, 윈도의 비율을 $q_i$라 하자. Jensen-Shannon 거리 $d$는 Jensen-Shannon 발산의 제곱근이다. 차이가 작을 때 자연로그 기준 발산은 다음과 같이 근사된다(유도는 테일러 전개이고 여기서는 생략한다).

    합에 $n$을 곱한 값은 chi-square 적합도 통계량이다. 이 통계량은 같은 분포에서 자유도 $k-1$인 chi-square 분포를 근사적으로 따른다. 평균이 $k-1$이므로 본문의 식이 나온다. 평균 제곱의 제곱근이라 실제 평균보다 조금 크다.

    판정 확률도 같은 식에서 나온다. 거리가 0.1 이상이라는 말은 통계량이 $8n(0.1)^2$ 이상이라는 말이다.

    오경보를 줄이는 선택

    오경보를 줄이는 방법은 윈도를 키우는 것과 판정 방법을 바꾸는 것이다. 다만 표본이 커지면 가설 검정 쪽에서 반대 방향의 문제가 나타난다. 윈도 크기부터 본다.

    윈도 크기 선택

    허용할 오경보 비율을 정하면 필요한 윈도 크기를 구할 수 있다. 아래 표는 오경보 5%, 임곗값 0.1인 경우다. 측정은 컬럼 판정 비율이 5% 이하가 되는 가장 작은 윈도이고 윈도를 10~25행 간격으로 올리며 찾았다.

    윈도 크기를 구하는 식

    허용할 오경보 비율을 $\alpha$, 거리 임곗값을 $t$라 하자. $\chi^2_{k-1,\,1-\alpha}$는 자유도 $k-1$인 chi-square 분포의 상위 $\alpha$ 지점이다.

    식과 측정의 차이는 측정값 기준 최대 15%였다. 필요한 크기는 어느 판정을 줄일지에 따라 다른데, 이 데이터에서 데이터셋 판정은 윈도 200이면 1%지만 모든 컬럼의 판정을 5%로 두려면 800행이 넘는다. 그런데 윈도를 키우면 그만큼 변화를 늦게 알게 된다. 요청이 하루 1000건이면 윈도 500은 반나절 치다. 얼마나 빨리 알아야 하는지와 오경보를 얼마나 견딜지를 먼저 정해야 크기를 고를 수 있다.

    윈도를 키우지 못하면 다른 설정을 쓸 수 있다.

    • 컬럼별 임곗값: 범주가 많은 컬럼의 임곗값을 올린다. DatasetDriftMetric(per_column_stattest_threshold={...})로 주어야 드리프트 컬럼 비율이 바뀐다. 실습 윈도에서 세 컬럼을 0.3으로 주면 0.5가 0.125로 내려갔다. ColumnDriftMetric의 stattest_threshold는 그 컬럼의 판정만 바꾸고 비율은 0.5 그대로였다. 거리는 임곗값을 올리면 덜 민감해지지만 p값 방식은 임곗값을 올리면 오히려 더 민감해진다.
    • 범주 묶기: 드문 범주를 묶어 $k$를 줄인다.
    • 데이터셋 기준: DatasetDriftMetric(drift_share=...)로 앞의 0.5를 올린다. 컬럼 몇 개만 실제로 바뀐 경우를 놓치기 쉽다.
    • 연속 판정: 연속 몇 회 넘을 때만 알린다. 겹치지 않는 윈도일 때 효과가 있다. 책의 서비스는 요청마다 윈도를 한 행씩 밀기 때문에 이웃 윈도가 99행을 공유한다. 윈도 100에서 한 행씩 밀면 오경보 55%가 3회 연속 50%, 10회 연속 38%였다. 겹치지 않게 자르면 행 순서 300개 평균으로 3회 연속 18%, 5회 연속 6%였다(결과).

    판정 방법과 reference 크기

    거리 대신 chi-square를 쓰면 어떨까. 판정 방법은 stattest 인자로 고를 수 있으므로 reference를 유지한 채 방법만 바꿀 수 있다. reference를 줄이는 길도 있다. 책의 보고서 구성으로 잰 report.run의 중앙값은 reference 전체일 때 약 400ms, 1000행일 때 약 40ms라 판정 비용 때문에 reference를 줄일 이유가 있고, 1000행으로 줄이면 기본 규칙이 값이 3개 이상인 컬럼에 chi-square를, 값이 2개인 Sex에 Z 검정을 고른다. 아래는 두 경우의 데이터셋 드리프트 판정 비율이다. 첫 열은 앞 표의 값이고 나머지 두 열은 Evidently로 윈도를 300번 판정한 값이다(결과).

    윈도 크기 기본값(거리, reference 전체) stattest="chisquare", reference 전체 기본값, reference 1000행
    50 98% 0.7% 1.7%
    100 57% 0.7% 5.7%
    200 1% 0% 9.0%

    reference를 유지하고 방법만 바꾸면 데이터셋 오경보는 1% 아래다. 컬럼 판정은 대체로 4~11%였고 범주 대부분의 기대 개수가 5보다 작은 Native_country만 14~23%로 높았다. 반면 reference를 줄이면 윈도가 커질수록 오경보가 늘었는데, 기대 개수를 만드는 방식에서 이유를 찾을 수 있다.

    # evidently/calculations/stattests/chisquare_stattest.py (v0.5.0, 발췌)
k_norm = current_data.shape[0] / reference_data.shape[0]
f_exp = [ref_feature_dict[key] * k_norm for key in keys]
f_obs = [current_feature_dict[key] for key in keys]
p_value = chisquare(f_obs, f_exp)[1]

    기대 개수는 current의 행 수로 환산한 reference의 개수다. 그런데 reference도 표본인데 이 코드는 reference 비율을 오차 없는 참값으로 두므로, 윈도가 reference 크기에 가까워질수록 통계량이 커진다. 드문 범주가 없는 Relationship도 reference 1000행에서 윈도 50일 때 8%, 200일 때 11%, 500일 때 21%, 1000일 때 35%였다(결과).

    reference를 줄이면 current에는 있는데 reference 1000행에는 없는 범주가 나올 수도 있는데, 이때는 기대 개수가 0이 되어 통계량이 무한대로 가고 p값이 0이 된다. Native_country는 윈도 200에서 84%의 시행에 이런 범주가 나왔고 그때의 판정은 모두 드리프트였다(결과).

    그래서 비용 때문에 reference를 줄이더라도 방법은 stattest로 따로 고르고, 줄인 reference의 표본 오차가 판정에 영향을 준다는 점을 감안하는 편이 낫다.

    큰 표본의 판정

    행이 독립이고 reference가 크면 거리 판정의 오경보는 윈도가 작을 때 생긴다. 반대로 표본이 커지면 가설 검정 쪽에서 다른 문제가 나타나는데, 앞의 예시처럼 p값은 표본이 커질수록 작아지기 때문이다. 이를 보려고 범주 5개 분포에서 45%를 45.5%로, 5%를 4.5%로 옮긴 표본을 원래 분포의 같은 크기 표본과 비교했다. 검정은 두 표본의 개수를 합친 비율로 기대 개수를 만들어 양쪽의 오차를 함께 보는 두 표본 chi-square이고, 표는 1000번 실행의 값이다.

    표본 크기 p값 중앙값 p<0.05 비율 거리 평균
    1만 0.21 22% 0.0123
    10만 1.9e-6 99.5% 0.0090
    100만 2.3e-62 100% 0.0086

    100만 건이면 chi-square는 이 변화를 확실하게 판정한다. 분포를 실제로 바꿨으니 판정이 틀린 것은 아니고, 변화 없는 표본을 주면 100만 건에서도 4.1%라 오경보가 늘어난 것도 아니다. 그런데 chi-square는 대응할 필요가 없는 작은 변화까지 유의하다고 답한다. 거리는 실제 차이 0.0085로 수렴해 기준 0.1에 한참 못 미친다. 그래서 표본이 크면 얼마만큼의 변화에 대응할지를 따로 정해야 한다.

    Evidently의 기본 규칙은 reference 크기로 방법을 고르지만, 이번 측정에서 판정을 가른 것은 윈도 크기였다. 그래서 방법은 기본 규칙에 맡기지 않고 윈도 크기와 허용할 변화 크기를 보고 stattest와 임곗값으로 직접 정하는 편이 낫다.


    정리

    책의 0.875와 스터디 캡처의 0.5를 같은 데이터에서 다시 얻는 데서 시작해 그 값이 윈도 크기와 어떻게 묶이는지 따라갔다. 두 값이 나온 이유는 고정 기준 0.1이 윈도 크기를 반영하지 않아서다. 윈도 100에서 범주가 많은 세 컬럼은 표본 오차만으로 거의 늘 기준을 넘고 나머지가 확률적으로 더해진다. 0.5와 0.875는 무작위 윈도의 드리프트 컬럼 비율 분포 안의 값이다.

    이 데이터의 데이터셋 판정은 윈도 200이면 1%지만, 컬럼 판정까지 정하려면 허용할 오경보 비율을 먼저 정하고 윈도 크기 식으로 구해야 한다. 범주가 많으면 윈도를 키우기보다 판정 방법이나 임곗값을 바꾸는 쪽이 낫다.

    Adult는 행 하나가 사람 한 명인 표 데이터라 행끼리 독립이라고 볼 수 있고 표본 수는 행 수다. 6.2.2편에서는 공개 주행 영상 데이터로 옮겨 행이 프레임일 때 표본 수가 무엇이 되는지 본다.
